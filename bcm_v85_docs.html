Event Bus

Wszystkie moduły komunikują się przez publish/subscribe event bus. Moduł publikuje dane (np. obd.rpm), a inne moduły subskrybują te tematy. Event bus wspiera również IPC (Unix socket) dla komunikacji między procesami.

03Specyfikacja ekranów (A1-A8)

Ekran główny (7/8") wyświetla 8 ekranów funkcjonalnych + ekran ustawień. Nawigacja: dotyk (swipe lub nav bar) + przycisk SWC na kierownicy.

A1

Dashboard — Hub główny

Temperatura silnika (gauge okrągły), poziom paliwa (progress bar z glow), powiadomienia systemowe (ciśnienie opon, serwis, trasa), media BT (teraz grane), szybkie statystyki (śr. prędkość, czas jazdy, napięcie).

A2

Android Auto — Kiosk

Android Auto osadzony jako iframe/karta w ramach BCM. Nagłówek BCM (logo, czas, temp) i pasek nawigacji widoczne. Stream video z OpenAuto Pro. Fallback: placeholder "Podłącz Android Auto". Touch pass-through do AA.

A3

Podróż i spalanie

GPS tracking: ciągłe logowanie trasy do SQLite. Wizualizacja trasy na mini mapie. Historia podróży (ostatnia, dziś, tydzień, miesiąc). Wykres spalania z prawdziwymi danymi (oś Y: L/100km, oś X: czas). Profil jazdy (ECO/NORMAL/DYNAMIC/SPORT). Eksport danych podróży.

A4

Pogoda i mapa

Leaflet.js z kafelkami OSM. Wyszukiwanie lokalizacji (ekran dotykowy). Nakładka ruchu drogowego na żywo (TomTom/HERE API). Aktualna pogoda + prognoza 3-dniowa. Wiatr, wilgotność, odczuwalna temperatura. Marker GPS z pozycji event bus.

A5

Serwis i diagnostyka

Lista diagnostyczna: silnik, olej, akumulator, opony (TPMS). Odczyt kodów błędów DTC z ECU (KWP2000 readDiagnosticTroubleCodes). Kasowanie DTC (clearDiagnosticInformation) z dialogiem potwierdzenia. Szkic auta z ilustracją. Licznik do następnego przeglądu.

A6

Nagrania DVR

Przeglądarka nagrań przód/tył. Siatka miniatur z datą i rozmiarem. Odtwarzanie HTML5 video z nakładką GPS (prędkość, pozycja, kierunek, czas). Filtrowanie: kamera, zakres dat. Informacja o pamięci (wewnętrzna + USB). Eksport USB: zaznaczenie nagrań → kopiowanie na pendrive z paskiem postępu.

A7

Performance

Gauge boost turbo: SVG arc gauge (0-1.5 BAR) z kolorowymi strefami (vacuum/low/high/overboost). Timer 0-100 km/h: GPS-based, historia ostatnich 10 pomiarów, najlepszy czas podświetlony. Statystyki: peak boost, RPM bar, prędkość, szacunek G-Force (z GPS heading), szacunek mocy chwilowej.

A8

Telefon BT

Dialer: klawiatura numeryczna (0-9, *, #), przycisk dzwonienia i usuwania. Kontakty: synchronizacja PBAP z telefonu, wyszukiwanie, tap-to-call. Historia: połączenia przychodzące/wychodzące/nieodebrane z ikoną typu, czasem i długością. Incoming call overlay: akceptacja/odrzucenie z danymi dzwoniącego (pulsujące ring_volume). Active call overlay: timer, mute/unmute (dual mic routing), hangup. Mikrofon #2 (USB mini/clip) dedykowany dla telefonu i Android Auto.

⚙

Ustawienia

Motyw (Heritage/Modern/Autodelta). Język (PL/EN). Jednostki (km/h↔mph, °C↔°F). Parowanie Bluetooth (skanowanie, parowanie, łączenie, usuwanie urządzeń). Konfiguracja WiFi AP (SSID, hasło, włącz/wyłącz). Jasność ekranów. Konfiguracja czujnika deszczu. Konfiguracja oświetlenia (follow-me-home czas).

Mały ekran 4.3" (port 5003)

Wyświetlacz nie-dotykowy z karuzelą danych. Auto-cyklowanie co 5 sekund lub zmiana przyciskiem SWC. Nagłówek z czasem i datą zawsze widoczny. Podczas cofania: pełnoekranowy overlay z kamerą + 4 paski czujników parkowania (LL, CL, CP/CR, PP/RR).

Karuzela danych: Poziom paliwa (%) → Temperatura płynu chłodniczego (°C) → Temperatura zewnętrzna (°C) → Temperatura wewnętrzna (°C, jeśli czujnik dostępny)

06Nowe moduły sprzętowe

Czujnik deszczu + wycieraczki

Optoisolowany sygnał cyfrowy z czujnika deszczu na zderzaku (GPIO 87 wejście). Przekaźnik aktywujący wycieraczki (GPIO 88 wyjście). Logika: wykrycie deszczu → aktywacja wycieraczek na konfigurowalny czas. Czułość: lekki / umiarkowany / intensywny → różne prędkości wycieraczek.

07Android Auto — integracja kiosk

Architektura

OpenAuto Pro działa na OPi jako osobny proces. BCM osadza stream video AA jako iframe/card na ekranie A2. Nagłówek BCM (logo, czas, temperatura) i pasek nawigacji pozostają widoczne — użytkownik może przełączyć ekran bez opuszczania AA.

Połączenie

  • Bezprzewodowe: WiFi AP (SSID: ALFA, hasło konfigurowane) — telefon łączy się do hotspotu OPi
  • Przewodowe: USB-C OTG — telefon podłączony kablem
  • Video stream: MJPEG z Xvfb (DISPLAY=:99) via ffmpeg → endpoint /aa/stream
WiFi AP vs LTE: Hotspot WiFi AP dla AA działa na wewnętrznym WiFi OPi. LTE modem ma osobne połączenie (USB). Nie kolidują ze sobą — AA używa WiFi direct, internet idzie przez LTE.

Fallback

Gdy AA nie jest podłączone, ekran A2 wyświetla placeholder z instrukcją połączenia (ikona telefonu + tekst "Podłącz Android Auto").

14Zarządzanie energią

Maszyna stanów — deep idle (bez poweroff) ZMIANA

OS Boot → splash (mpv) → ignition watcher polls GPIO + evdev │ ├─ [zapłon ON lub SWC MODE] → boot_mode cold/warm → start BCM │ cold: skip init screen → ostatni ekran │ warm: init 4s → ostatni ekran │ ├─ [zapłon OFF lub SWC MODE] → stop BCM → deep idle (OS działa) │ └─ [12h timer] → past_12h=True → następne wake = cold-like (splash)

Deep idle: OS nigdy nie robi sudo poweroff. Po zapłonie OFF, BCM app zatrzymuje się, ale OPi działa dalej na baterii backup. Po 12h bez cold boot, następne wake odtwarza splash (mpv) i resetuje okno 12h.

SWC power toggle: Przycisk SWC_MODE (KEY_F10) może włączyć BCM ze standby ORAZ wyłączyć BCM nawet gdy zapłon jest ON. Zarówno SWC jak i zapłon budzą BCM ze standby.

Ignition: GPIO 7 / PA7 (wejście optoisolowane, pin 29). Central lock: GPIO 20 / PA20 (pin 37).

Konfiguracja: power.standby_max_hours: 12, power.splash_duration_seconds: 15 — czas trwania splasha konfigurowalny, domyślnie 15s.

Stan: /tmp/bcm_power_state — plik stanu (boot_mode, first_boot_ts) odczytywany przez frontend via /api/boot_mode.

Implementacja: src/power/ignition_watcher.py (StandbyTimer, EvdevWakeMonitor, write_state)

Podświetlenie

PWM 1000Hz na GPIO 32 (4.3") i GPIO 33 (7/8"). Płynne przejścia (50 kroków, 1s). Jasność 0-100% niezależnie per ekran. Auto-jasność z czujnika LDR (Arduino A1).

Shutdown (graceful app cleanup)

Sekwencja: zatrzymaj DVR → zapisz stan → flush logi → sync → OS zostaje w deep idle (brak sudo poweroff). Cykl życia OS zarządzany wyłącznie przez ignition watcher.

Tryb RADIO NOWE

Uruchamiany przyciskiem SWC MODE (lub fizycznym Power). Ekran główny 7/8" ON, audio ON, mały ekran 4.3" OFF. Moduły OBD/parking/DVR wyłączone. Pobór: ~2A 5V + wzmacniacze audio. Wyjście: przycisk SWC MODE ponownie LUB uruchomienie silnika (zapłon → ACTIVE). Auto-timeout po konfigurowalnym czasie (30/60/120 min) aby nie rozładować akumulatora.

Bateria backup NOWE

Dodatkowa mała bateria (oddzielna od akumulatora samochodu) zasila OPi podczas 12h okna standby (deep idle). Arduino jest zawsze zasilane (bateria backup) i wysyła USB HID keycody.

Li-ion 18650 3.7V 5000mAh z ładowarką TP4056 i boost MT3608 (3.7V→5V). Przekaźnik przełącza między akumulatorem samochodowym a baterią backup. W trybie deep idle bateria zasila: OPi (OS idle) + Arduino + modem LTE + GPS. Pobór: ~0.15A, wytrzymałość: ~30 godzin.

Implementacja: src/power/battery.py — monitorowanie napięcia baterii (Arduino ADC), progi: full 4.2V, nominal 3.7V, low 3.3V, krytyczny 3.0V.

Detekcja wypadku NOWE

Po wykryciu wypadku (GPS: spadek prędkości >30 km/h w <2s, lub akcelerometr >3G) — bateria backup zapewnia zasilanie DVR przez 60s. Nagrania wypadku chronione przed nadpisaniem.

Implementacja: src/camera/crash_detect.py
