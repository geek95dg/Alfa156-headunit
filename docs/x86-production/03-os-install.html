OS Installation Debian 13 (Trixie) on Lenovo M910q — minimal server install with driver setup

BIOS Settings

Before installing, configure the M910q BIOS for headless automotive operation. Press F1 at the Lenovo splash screen to enter BIOS Setup.

Menu Path Setting Value
Startup → Boot Priority Primary Boot Sequence USB HDD first (for installation)
Security → Secure Boot Secure Boot Disabled
Power → After Power Loss After Power Loss Power On
Devices → USB Setup USB Legacy Support Disabled
After Power Loss = Power On

This setting is critical for automotive use. When the 12 V → 20 V converter supplies power (ignition on), the M910q will boot automatically without pressing the power button. Combined with ACPI suspend, this gives seamless ignition-based start/stop behaviour.

Disable Secure Boot

Secure Boot must be disabled to allow unsigned kernel modules (e.g. out-of-tree WiFi drivers) and to avoid boot issues with the minimal Debian installation. The M910q will be running in a closed automotive environment, so Secure Boot provides no practical benefit.

Install Debian 13 (Trixie)

Prepare Installation Media

Download the netinst amd64 ISO from https://www.debian.org/devel/debian-installer/ (Trixie). Write it to a USB drive: 

# From a Linux workstation:
sudo dd if=debian-13-amd64-netinst.iso of=/dev/sdX bs=4M status=progress conv=fsync

# Or use Rufus / Etcher on Windows/macOS

Plug the USB drive into the M910q and boot. The installer should launch automatically if USB boot priority was set in BIOS.

Partitioning

Use manual partitioning with the following layout on the NVMe SSD:

Partition Size Type / Mount Purpose
ESP 512 MB – 1 GB EFI System Partition (/boot/efi) UEFI bootloader, GRUB
Root Remaining space ext4 (/) OS, BCM application, dashcam recordings
No swap partition

Do not create a swap partition. The M910q has 8 GB RAM which is more than sufficient. We will configure zram (compressed RAM swap) post-install, which is faster than disk swap and avoids unnecessary SSD writes that reduce NVMe lifespan.

Software Selection

At the Software selection screen (tasksel), uncheck everything except:

  • SSH server — for remote access during setup
  • standard system utilities — basic CLI tools
No desktop environment

Do not install GNOME, KDE, Xfce, or any desktop environment. BCM uses a minimal X11 session with matchbox-window-manager and Chromium in kiosk mode. A full desktop environment wastes RAM, slows boot, and interferes with the kiosk setup described in 08 — Kiosk Display.

Post-install Setup

After the first boot, log in as the regular user and configure sudo access and non-free firmware repositories.

Enable sudo

# Switch to root
su -

# Install sudo and add user to sudo group
apt install -y sudo
usermod -aG sudo abner

# Exit root shell
exit

# Log out and back in for group membership to take effect

Enable Non-free Firmware

# Add contrib, non-free, and non-free-firmware to apt sources
grep non-free /etc/apt/sources.list || \
    sudo sed -i 's/main$/main contrib non-free non-free-firmware/' /etc/apt/sources.list

sudo apt update
Why non-free-firmware?

The Intel GPU (i915), WiFi (iwlwifi or mt7921), and Bluetooth adapters all require binary firmware blobs from the non-free-firmware repository. Without this, VAAPI hardware decode, WiFi AP mode, and Bluetooth will not function.

Static IP (Optional)

If connecting the M910q to a workshop network for remote setup via SSH, a static IP avoids DHCP lookup delays and makes the machine easier to find. 

sudo tee /etc/network/interfaces.d/static >/dev/null <<EOF
auto enp0s31f6
iface enp0s31f6 inet static
    address 192.168.1.100
    netmask 255.255.255.0
    gateway 192.168.1.1
    dns-nameservers 8.8.8.8 1.1.1.1
EOF

sudo systemctl restart networking
Interface name

The M910q's built-in Intel I219-LM Ethernet typically appears as enp0s31f6. Verify with ip link show and adjust the config if your interface name differs.

System Packages

Install all required packages in a single apt install command. This covers the display server, kiosk browser, GPU drivers, audio stack, WiFi/BT firmware, camera tools, and system utilities. 

sudo apt install -y \
    python3 python3-venv python3-full python3-dev python3-serial \
    git curl wget \
    xserver-xorg xinit x11-xserver-utils xinput xdotool xvfb \
    matchbox-window-manager unclutter chromium \
    intel-media-va-driver vainfo libva-drm2 \
    pipewire pipewire-pulse wireplumber alsa-utils mpv \
    firmware-mediatek bluez bluez-tools network-manager \
    hostapd dnsmasq iw wireless-tools \
    ffmpeg v4l-utils \
    acpid \
    zram-tools fonts-dejavu-core

Fenvi FU-AX1800 Driver Setup

If you upgraded the M910q's WiFi card to the Fenvi FU-AX1800 (MediaTek MT7921 chipset), the firmware-mediatek package installed above provides the required firmware. No out-of-tree driver compilation is needed — the mt7921e kernel module is included in the Debian 13 kernel.

Verify MT7921 Detection

# Check that the card is detected on the PCI bus
lspci | grep -i mediatek
# Expected output:
#   Network controller: MEDIATEK Corp. MT7921 802.11ax PCI Express Wireless Network Adapter

Blacklist Intel WiFi (if present)

If the original Intel 8265 card is still installed in the M.2 slot alongside the Fenvi (e.g. via an adapter), blacklist its driver to avoid interface conflicts: 

# Prevent iwlwifi from loading
echo "blacklist iwlwifi" | sudo tee /etc/modprobe.d/blacklist-intel-wifi.conf

Verify WiFi Interface

# Confirm the wireless interface is up
ip link show | grep wl
# Should show a wlp* interface (e.g. wlp1s0 or wlp2s0)
Only one M.2 E-key slot

The M910q has a single M.2 E-key slot for WiFi. If you install the Fenvi FU-AX1800, it replaces the Intel 8265 — you cannot have both installed simultaneously without an external USB adapter. Remove the Intel card before inserting the Fenvi.

zram Setup

Configure zram to provide compressed in-memory swap. This is faster than SSD swap and eliminates unnecessary NVMe write wear. With 8 GB RAM and lz4 compression at 50%, this provides approximately 4 GB of effective swap space. 

# Configure zram: lz4 compression, 50% of RAM
echo -e 'ALGO=lz4\nPERCENT=50' | sudo tee /etc/default/zramswap

# Enable zramswap service
sudo systemctl enable zramswap
Why lz4?

The lz4 algorithm offers the best decompression speed of any available option. For swap, decompression speed matters more than compression ratio since reads (page-ins) are latency-critical. With an i5-6400T, lz4 swap access is nearly as fast as uncompressed RAM.

Verify VAAPI

After installing all packages and rebooting, verify that hardware video acceleration is working correctly on the Intel HD 530 GPU. 

# Reboot to load all drivers and firmware
sudo reboot

After reboot, run:

# Check VAAPI driver and supported profiles
vainfo

Expected output should include lines like:

vainfo: VA-API version: 1.xx
vainfo: Driver version: Intel iHD driver - x.x.x
vainfo: Supported profile and entrypoints
      VAProfileH264Main               : VAEntrypointVLD
      VAProfileH264High               : VAEntrypointVLD
      VAProfileH264ConstrainedBaseline: VAEntrypointVLD
      VAProfileHEVCMain               : VAEntrypointVLD
      ...
VAProfileH264 is the key entry

BCM's camera feeds and dashcam recordings use H.264. As long as VAProfileH264Main and VAProfileH264High appear with VAEntrypointVLD (decode), hardware-accelerated video playback will work. HEVC (H.265) support is a bonus for future use.

vainfo fails or shows no profiles?

If vainfo returns an error or shows no profiles, check that: (1) intel-media-va-driver is installed, (2) non-free-firmware is in your apt sources (the i915 firmware is needed), and (3) you rebooted after installation. Run sudo apt install --reinstall intel-media-va-driver and reboot if issues persist.
