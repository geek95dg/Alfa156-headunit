K-Line OBD-II — ECU Communication K-Line adapter build and Bosch EDC15C7 diagnostics for Alfa Romeo 156 1.9 JTD

Overview

The Alfa Romeo 156 1.9 JTD (8V, 2000–2005) does not have a CAN-bus OBD-II interface. Instead, the Bosch EDC15C7 engine ECU communicates over a single-wire K-Line bus using the ISO 14230 (KWP2000) protocol. This is a serial communication line operating at 10400 baud, where a single wire carries bidirectional data between the diagnostic tester and the ECU.

BCM uses K-Line to read live engine data — RPM, vehicle speed, coolant temperature, fuel consumption, turbo boost pressure, and more — and displays it on the dashboard gauges in real time. The connection is read-only; BCM never writes to the ECU or modifies any engine parameters.

Read-only access — safety first

BCM operates in read-only diagnostic mode. It uses KWP2000 service 0x21 (readDataByLocalIdentifier) to request sensor data. No write, programming, or reset commands are ever sent to the ECU. Do not modify the software to send write commands unless you fully understand the consequences — incorrect ECU writes can cause engine damage or unsafe driving conditions.

Hardware — K-Line Adapter Build

The K-Line adapter converts USB serial (3.3V/5V TTL) to the 12V single-wire K-Line bus. It consists of three components:

Components

Component Description Approx. Cost (PLN)
CP2102 USB-UART module USB to 3.3V/5V TTL serial converter. Provides TX, RX, GND, and 5V output. 8–15
L9637D transceiver IC ISO 9141 / ISO 14230 K-Line transceiver. Converts TTL logic to 12V K-Line signalling. 8-pin DIP package. 8–15
510Ω resistor Pull-up resistor between 12V battery supply and the K-Line. Keeps the line HIGH when idle. 0.50–1
100nF ceramic capacitor Decoupling capacitor between VCC and GND on the L9637D for noise filtering. 0.50–1
12V supply Taken from OBD-II pin 16 (permanent battery 12V). —

Total cost: ~25–40 PLN

TX/RX cross-over

The CP2102 TX pin connects to the L9637D RX (pin 5), and CP2102 RX connects to L9637D TX (pin 6). This is the standard UART cross-over — transmit on one side goes to receive on the other.

L9637D Pinout (8-pin DIP)

Pin Name Direction Description Connect to
1 K I/O K-Line bus (bidirectional, 12V levels) OBD-II Pin 7
2 VS Power Battery voltage sense / pull-up supply 12V via 510Ω resistor
3 VCC Power Logic supply voltage (4.5–5.5V) CP2102 5V output
4 GND Power Ground reference Common GND (CP2102 + OBD-II pin 4)
5 RX Input Serial data input from tester (TTL) CP2102 TX
6 TX Output Serial data output to tester (TTL) CP2102 RX
7 NC — Not connected —
8 EN Input Enable (active high, tie to VCC) VCC (pin 3)

Connection to Car

OBD-II Port Location

In the Alfa Romeo 156, the OBD-II diagnostic port is located under the steering column, on the left side, near the fuse box. It faces downward and may be covered by a small plastic cap. The connector is a standard 16-pin Type A (passenger car) OBD-II socket.

OBD-II Pinout (Used Pins)

Only 4 of the 16 OBD-II pins are used for K-Line communication:

OBD-II Pin Signal Description Wire Colour (typical)
4 Chassis GND Ground reference — connect to L9637D GND and CP2102 GND Black / Brown
5 Signal GND Signal ground — connect together with pin 4 Black / Brown
7 K-Line ISO 14230 data line — connect to L9637D pin 1 (K) White / Grey
16 Battery +12V Permanent battery voltage — connect to L9637D pin 2 (VS) via 510Ω Red
No L-Line needed

Some older ISO 9141 implementations use both K-Line (pin 7) and L-Line (pin 15). The Bosch EDC15C7 in the Alfa 156 1.9 JTD uses K-Line only. Pin 15 is not connected.

Software Configuration

The K-Line serial port is configured in config/bcm_config.yaml: 

serial:
  kline:
    port_x86: /dev/ttyUSB_kline    # stable symlink via udev rule
    baudrate: 10400                # ISO 14230 standard baud rate
    ecu_address: 1                 # 0x01 = EDC15C7 engine ECU

udev Rule for Stable Device Naming

The CP2102 USB-UART module must have a stable /dev/ symlink so BCM can find it regardless of USB enumeration order. Create or verify the udev rule (as described in 04 — Software § USB Device Naming): 

# /etc/udev/rules.d/99-bcm-usb.rules
# K-Line adapter (CP2102)
SUBSYSTEM=="tty", ATTRS{idVendor}=="10c4", ATTRS{idProduct}=="ea60", SYMLINK+="ttyUSB_kline"

Reload and trigger after creating or editing the rule: 

sudo udevadm control --reload-rules
sudo udevadm trigger

Verify the Symlink

ls -la /dev/ttyUSB_kline
# Expected output:
# lrwxrwxrwx 1 root root 7 ... /dev/ttyUSB_kline -> ttyUSB0
User permissions

The BCM user must be in the dialout group to access serial ports without root. The setup script (phase 12) adds this automatically, or do it manually: sudo usermod -aG dialout $USER (log out and back in to apply).

Communication Protocol

The K-Line communication follows the ISO 14230 (KWP2000) protocol. BCM implements this in two layers: src/obd/kline.py handles the physical layer, and src/obd/kwp2000.py handles the application-layer diagnostic services.

5-Baud Initialization Sequence

Before normal communication can begin, the tester must perform a slow-init handshake at 5 baud to wake up the ECU. The full sequence:

  1. Send ECU address at 5 baud — Pull the K-Line low for 200ms per bit to transmit the target ECU address (0x01 for EDC15C7). The 10-bit frame is: start bit (0), 8 data bits LSB-first (00000001 = 0x01), stop bit (1). Total time: 10 × 200ms = 2 seconds.
  2. Switch to 10400 baud — After the address is sent, reconfigure the UART to 10400 baud, 8N1 (8 data bits, no parity, 1 stop bit).
  3. Receive sync byte — The ECU responds with 0x55 (01010101 binary), which the tester can use to verify baud rate synchronization.
  4. Receive two key bytes (KB1, KB2) — The ECU sends two key bytes that identify its supported protocol variant. For EDC15C7, these are typically 0x08 0x08 (KWP2000 with physical addressing).
  5. Send inverted KB2 — The tester acknowledges by sending the bitwise inverse of KB2: (~KB2) & 0xFF.
  6. Receive inverted address echo — The ECU confirms the handshake by sending the bitwise inverse of the ECU address: (~0x01) & 0xFF = 0xFE. Communication is now established.

KWP2000 Timing Constants

Parameter Value Description
P1 max 20 ms Maximum inter-byte time in ECU response
P2 min / max 25–50 ms Time between tester request and ECU response
P3 min 55 ms Minimum time between ECU response and next tester request
P4 min 5 ms Minimum inter-byte time in tester request

KWP2000 Diagnostic Session

After the 5-baud init handshake, BCM starts a diagnostic session and begins polling data:

Step Service SID Parameters Description
1 startDiagnosticSession 0x10 Mode 0x81 (default session) Opens a diagnostic session with the ECU
2 testerPresent 0x3E No parameters Keepalive sent every 2 seconds to prevent session timeout
3 readDataByLocalIdentifier 0x21 Local ID (e.g., 0x01 for RPM) Reads a single parameter from the ECU
4 stopDiagnosticSession 0x20 No parameters Closes the session on shutdown

KWP2000 Message Format

Each message uses physical addressing with the following structure: 

[Format] [Target] [Source] [Data...] [Checksum]

Format byte: 0x80 | data_length   (physical addressing, length in format byte)
Target:      0x01                  (ECU address)
Source:      0xF1                  (tester address)
Checksum:    sum of all preceding bytes, masked to 8 bits

Example — read RPM (local ID 0x01):
  Request:  [0x82] [0x01] [0xF1] [0x21] [0x01] [0x96]
  Response: [0x83] [0xF1] [0x01] [0x61] [0x01] [RPM_HI] [RPM_LO] [CS]

ECU Data — PID Definitions

The Bosch EDC15C7 exposes 9 parameters via KWP2000 local identifiers. These are defined in src/obd/edc15c7.py:

Local ID Parameter Unit Scale Bytes Dashboard Gauge
0x01 Engine RPM rpm ×0.25 2 Primary (tachometer)
0x02 Vehicle Speed km/h direct 1 Primary (speedometer)
0x03 Coolant Temperature °C −40 offset 1 Primary (temp gauge)
0x04 Fuel Consumption Rate L/h ×0.01 2 Secondary
0x05 Injector Quantity mg/stroke ×0.01 2 Secondary
0x06 Battery Voltage V ×0.1 1 Status bar
0x07 Turbo Boost Pressure mbar direct 2 Secondary (boost gauge)
0x08 Intake Air Temperature °C −40 offset 1 Secondary
0x09 Throttle Position % ×0.4 1 Secondary

Decoding Examples

# Engine RPM: 2 bytes big-endian, multiply by 0.25
raw = [0x0F, 0xA0]    # 4000 decimal
rpm = ((0x0F << 8) | 0xA0) * 0.25  # = 1000.0 rpm

# Coolant Temperature: 1 byte, subtract 40
raw = [0x69]           # 105 decimal
temp = 105 - 40        # = 65.0 °C

# Battery Voltage: 1 byte, multiply by 0.1
raw = [0x8C]           # 140 decimal
voltage = 140 * 0.1    # = 14.0 V

# Turbo Boost Pressure: 2 bytes big-endian, direct (mbar)
raw = [0x04, 0x4C]     # 1100 decimal
boost = (0x04 << 8) | 0x4C  # = 1100 mbar

Default Polling Group

BCM polls a subset of PIDs in a 100ms round-robin cycle by default. The DEFAULT_ACTIVE_PIDS from edc15c7.py are:

Local ID Parameter Event Topic
0x01 Engine RPM obd.rpm
0x02 Vehicle Speed obd.speed
0x03 Coolant Temperature obd.coolant_temp
0x04 Fuel Consumption Rate obd.fuel_rate
0x06 Battery Voltage obd.battery_voltage

With 5 PIDs at ~100ms each (plus P3 inter-request timing), the full polling cycle takes approximately 500–600ms, giving roughly 2 updates per second for each parameter. The remaining PIDs (injector quantity, turbo pressure, intake air temperature, throttle position) can be added to the active set in the configuration if needed.

Tester present keepalive

The EDC15C7Reader automatically sends a testerPresent (SID 0x3E) keepalive every 2 seconds to prevent the ECU from closing the diagnostic session due to inactivity. This runs in the same polling loop as the PID reads.

Verification

After building the adapter and connecting it, verify the entire chain from USB device to live ECU data:

Step 1: Check Adapter Detection

# Verify the CP2102 is detected by the kernel
lsusb | grep -i "cp2102\|10c4"
# Expected: Bus 00x Device 00x: ID 10c4:ea60 Silicon Labs CP210x UART Bridge

# Verify the udev symlink exists
ls -la /dev/ttyUSB_kline
# Expected: lrwxrwxrwx 1 root root 7 ... /dev/ttyUSB_kline -> ttyUSB0

Step 2: Check BCM Logs (Engine Running)

# Start the engine (key position II = ignition ON, or engine running)
# Then check BCM logs for ECU communication:
grep "edc15c7\|kline\|RPM\|coolant" /opt/bcm/logs/bcm.log | tail -10

# Expected output (example):
# obd.kline  - K-Line opened: /dev/ttyUSB_kline @ 10400 baud
# obd.kline  - 5-baud init response: sync=0x55 KB1=0x08 KB2=0x08
# obd.kline  - 5-baud init successful! ECU acknowledged.
# obd.edc15c7 - EDC15C7 reader started (polling 5 PIDs)

Step 3: Live Data via Web API

# Query the BCM REST API for live ECU data
curl -s http://localhost:5002/api/status | python3 -m json.tool | grep -E "rpm|speed|coolant"

# Expected output (with engine running):
#   "rpm": 850.0,
#   "speed": 0.0,
#   "coolant_temp": 72.0

Troubleshooting

No ECU Response

No ECU response during initialization

Symptom: BCM logs show 5-baud init: incomplete response (0 bytes) or No ECU acknowledgement received.

Check:

  • Verify 12V is present at OBD-II pin 16 with a multimeter
  • Confirm K-Line wire is connected to OBD-II pin 7 (not pin 6 or 14)
  • Check L9637D orientation — pin 1 dot/notch must face the correct direction
  • Verify the 510Ω pull-up resistor is between pin 16 (12V) and the K-Line
  • Measure L9637D VCC (pin 3): should be 4.5–5.5V
  • Make sure EN (pin 8) is tied to VCC

Timeout During Initialization

Timeout or partial response

Symptom: Sync byte 0x55 is received but key bytes are missing, or the ECU sends no response at all.

Check:

  • The ignition must be ON (key position II, dashboard lights on). The ECU does not respond when the ignition is OFF.
  • Try with the engine running — some ECUs only respond after cranking
  • Verify baud rate is 10400 in the configuration
  • Check for loose connections on the OBD-II plug

Wrong or Nonsensical Data

Data values are incorrect

Symptom: RPM shows 16000, coolant shows −40°C, or values jump randomly.

Check:

  • Verify ecu_address is set to 1 (0x01) in bcm_config.yaml — this must match the EDC15C7
  • Check for electrical noise — route K-Line wire away from ignition coils and alternator
  • Verify the 100nF decoupling capacitor is present on the L9637D
  • Check that TX/RX are not swapped between CP2102 and L9637D

Permission Denied

Cannot open serial port

Symptom: PermissionError: [Errno 13] Permission denied: '/dev/ttyUSB_kline'

Fix:

  • Add user to the dialout group: sudo usermod -aG dialout $USER
  • Log out and log back in (or reboot) for group changes to take effect
  • Verify with: groups $USER — should include dialout

Keepalive Failures

Frequent keepalive warnings

If the log shows Keepalive failed warnings, the ECU session may be timing out. This can happen if the polling loop is blocked or if there is excessive electrical noise. BCM will automatically attempt to re-initialize the connection after 10 consecutive errors. Check for other USB devices causing CPU load spikes or interrupt conflicts.
