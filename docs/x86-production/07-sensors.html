Environmental Sensors Temperature, parking, rain, light, and optoisolator wiring for vehicle signals

Overview

On the x86 platform (Lenovo M910q), there is no GPIO header. All sensors connect through the Arduino Pro Micro via USB. The Arduino reads sensor data, formats it as serial messages, and sends it to the BCM over /dev/ttyACM0 at 115200 baud. The Python module src/input/arduino_serial.py parses each message and publishes it to the event bus.

OPi vs x86

On the Orange Pi, sensors like the DS18B20 connect directly to the GPIO header via the kernel 1-Wire driver. On x86, the same sensor connects to the Arduino, which reads it and sends TEMP:23.5 over serial. The BCM software handles both paths transparently via the config option environment.temperature.source: arduino (default on x86).

DS18B20 Temperature Sensor

Specifications

  • Type: Dallas DS18B20 digital 1-Wire temperature sensor
  • Range: −55 °C to +125 °C (±0.5 °C accuracy)
  • Probe: Waterproof stainless steel, cable length ~1 m
  • Mounting: Under the front bumper (external air temperature)
  • Arduino pin: D14 (1-Wire data)

Wiring

                    4.7kΩ
  Arduino 5V ────┬──[####]──┐
                 │           │
                 │    DS18B20 (waterproof probe)
                 │    ┌─────────────┐
  Arduino D14 ───┼────┤ DQ (data)   │
                 │    │ VDD (power)  ├─── Arduino 5V
                 │    │ GND (ground) ├─── Arduino GND
                 │    └─────────────┘
                 │
  Arduino GND ───┘
Pull-up resistor

The 4.7 kΩ pull-up between DQ and 5 V is required for reliable 1-Wire communication. Without it, readings will be intermittent or stuck at 85.0 °C (the DS18B20 power-on default). Use powered mode (VDD connected), not parasitic mode.

Serial Output

The Arduino reads the DS18B20 every 10 seconds (DEFAULT_READ_INTERVAL = 10.0 in src/environment/ds18b20.py) and sends: 

TEMP:23.5

The BCM parses this and publishes vehicle.ext_temp_raw (float, degrees Celsius) to the event bus.

Configuration

# config/bcm.yml
environment:
  temperature:
    source: arduino        # "arduino" (x86 default) or "onewire" (OPi)
    read_interval: 10      # seconds between readings
    offset: 0.0            # calibration offset in °C

HC-SR04 Ultrasonic Parking Sensors (4×)

Specifications

  • Type: HC-SR04 ultrasonic distance sensor
  • Range: 2 cm to 250 cm (max distance capped at 2.5 m in firmware)
  • Measurement cycle: ~60 ms per sensor, ~240 ms for all four (sequential to avoid cross-talk)
  • Speed of sound: 343 m/s at ~20 °C

Pin Assignments

Sensor TRIG Pin ECHO Pin Position
Front Left (FL) D15 (shared) D16 Rear bumper, left
Front Right (FR) D15 (shared) A2 Rear bumper, centre-left
Rear Left (RL) D15 (shared) A3 Rear bumper, centre-right
Rear Right (RR) D15 (shared) A7 Rear bumper, right

Wiring (per sensor)

  Arduino D15 (TRIG) ─────────── HC-SR04 TRIG
  HC-SR04 ECHO ──────────────── Arduino D16 (or A2/A3/A7)
  HC-SR04 VCC ───────────────── Arduino 5V
  HC-SR04 GND ───────────────── Arduino GND
Voltage divider (optional)

The HC-SR04 ECHO output is 5 V, which is safe for the Arduino (also 5 V logic). If connecting to a 3.3 V board (such as an OPi), add a voltage divider: ECHO → 1 kΩ → GPIO → 2 kΩ → GND. This drops 5 V to ~3.3 V.

Mounting

  • Drill four 18 mm holes in the rear bumper, spaced ~30 cm apart
  • Angle sensors 15° outward from centre for wider coverage
  • Route cables through the bumper to the trunk area, then to the Arduino
  • Use silicone sealant around the sensor housings for waterproofing

Serial Output

PARK:FL=45,FR=123,RL=200,RR=180

Distances are in centimetres. Values near 250 indicate no obstacle detected (max range). The BCM parses this and publishes vehicle.parking_raw (dict with keys fl, fr, rl, rr mapping to integers) to the event bus.

Buzzer

A piezo buzzer connected to a spare Arduino digital pin provides audible feedback. Beep frequency increases as the closest sensor distance decreases: continuous tone below 30 cm, fast beep at 30–60 cm, slow beep at 60–120 cm, silent above 120 cm.

Rain Sensor

Specifications

  • Type: Capacitive digital rain sensor module (active-low output)
  • Arduino pin: D10 (via PC817 optoisolator)
  • 12 V car side → 5 V Arduino side (galvanic isolation)

Wiring through PC817 Optoisolator

The rain sensor operates on the car's 12 V circuit. A PC817 optocoupler provides galvanic isolation between the car electrical system and the Arduino: 

  CAR SIDE (12V)                         ARDUINO SIDE (5V)
  ══════════════                         ═════════════════

  12V rain signal ──[1kΩ]──┐              ┌─── Arduino 5V
                              │    PC817    │
                         LED+ ●────────● collector ── Arduino D10
                              │  opto   │        (10kΩ pull-up)
                         LED- ●────────● emitter ─── Arduino GND
                              │              │
  GND (car) ──────────────────┘              └─── (pull-up to 5V)
How it works

When rain is detected, the sensor pulls its output LOW (12 V side), current flows through the 1 kΩ resistor and the PC817 LED. The phototransistor conducts, pulling Arduino D10 LOW. The 10 kΩ pull-up holds D10 HIGH when no rain is detected.

Serial Output

RAIN:1    (rain detected)
RAIN:0    (dry)

The BCM publishes vehicle.rain (bool) to the event bus.

Auto-Wiper

When rain is detected, the BCM can automatically activate the wipers by sending a JSON command to the output Arduino (Nano): 

{"cmd":"wipers","duration":5}

Configuration

# config/bcm.yml
rain_sensor:
  enabled: true
  sensitivity: medium    # light=2s, medium=5s, heavy=10s wiper duration
  auto_wiper: true       # automatically trigger wipers on rain detection

Light Sensor (LDR)

Specifications

  • Type: Photoresistor (LDR) with 10 kΩ voltage divider
  • Arduino pin: A1 (analog input, ADC 0–1023)
  • Report interval: Every 2 seconds (LIGHT_REPORT_MS = 2000)

Wiring

  Arduino 5V ─── LDR ──┬── Arduino A1
                       │
                     [10kΩ]
                       │
  Arduino GND ─────────┘

The LDR and fixed 10 kΩ resistor form a voltage divider. In bright light, the LDR resistance drops, pulling A1 higher. In darkness, LDR resistance increases, pulling A1 lower. The firmware averages 4 ADC samples to reduce noise.

Serial Output

LIGHT:512

Value range: 0 (complete darkness) to 1023 (bright sunlight). Published as arduino.light_level (int) on the event bus.

Auto-Brightness

The BCM maps the ADC value to six display brightness levels:

ADC Range Ambient Brightness
0 – 100Night / tunnel15%
101 – 250Dusk / dawn30%
251 – 400Overcast45%
401 – 600Cloudy60%
601 – 800Partly sunny80%
801 – 1023Direct sunlight100%

Stalk Brightness Button

The spare column stalk button (Arduino A2, internal pull-up) allows manual brightness cycling. Each press sends KEY_F9 as a HID keycode, which the BCM intercepts to step through brightness levels, overriding auto-brightness until the next ignition cycle.

Optoisolator Circuits (PC817)

All 12 V car signals must be isolated from the 5 V Arduino using PC817 optocouplers. This protects the Arduino from voltage spikes, ground loops, and alternator noise on the car's electrical system.

Standard Circuit (same for all signals)

  CAR SIDE (12V)                         ARDUINO SIDE (5V)
  ══════════════                         ═════════════════

  12V signal ──────[1kΩ]──┐              ┌─── Arduino 5V
                              │    PC817    │       │
                         LED+ ●────────● collector ─┤
                              │  opto   │        [10kΩ] pull-up
                         LED- ●────────● emitter    │
                              │              │   Arduino Dx (input)
  GND (car) ──────────────────┘              │
                                       Arduino GND

When the 12 V signal is active, current flows through the 1 kΩ limiting resistor and the PC817 internal LED, causing the phototransistor to conduct and pulling the Arduino input pin LOW. The 10 kΩ pull-up holds the pin HIGH when no signal is present. All signals are therefore active-low on the Arduino side.

Pin Assignments

12 V Car Signal Arduino Pin Event Bus Topic Notes
Ignition (ACC 12 V) D2 vehicle.ignition_raw Main power-on signal; triggers suspend/wake
Handbrake D3 vehicle.handbrake Handbrake warning lamp wire
Door FL (front left) D4 vehicle.doors Door courtesy light switch
Door FR (front right) D5 Door courtesy light switch
Door RL (rear left) D6 Door courtesy light switch
Door RR (rear right) D7 Door courtesy light switch
Bonnet D8 vehicle.doors (bonnet key) Bonnet switch or mercury tilt sensor
Trunk D9 vehicle.doors (trunk key) Trunk courtesy light switch
Rain sensor D10 vehicle.rain Capacitive rain module output

Parts Required

  • 6× PC817 optocouplers (or equivalent: EL817, LTV-817)
  • 6× 1 kΩ resistors (1/4 W, LED current limiting)
  • 6× 10 kΩ resistors (1/4 W, pull-up)

Multiple signals can share a single PC817 if they are active at different times, but for reliability each signal should have its own optocoupler. Use a small perfboard or purpose-built PCB to mount all six circuits compactly.

Ground isolation

The PC817 provides galvanic isolation — the car GND and Arduino GND must not be connected together. If they share a ground, the optoisolator is bypassed and voltage spikes from the alternator or starter motor can damage the Arduino or the M910q USB port.

Verification

Test each sensor individually

# Open serial monitor
minicom -D /dev/ttyACM0 -b 115200

# ── Temperature ──
# Wait 10 seconds, should see:
#   TEMP:23.5
# Hold the probe in your hand — value should rise

# ── Light sensor ──
# Every 2 seconds:
#   LIGHT:512
# Cover the LDR — value should drop toward 0
# Shine a light — value should rise toward 1023

# ── Parking sensors ──
# Place hand in front of a sensor:
#   PARK:FL=15,FR=250,RL=250,RR=250
# Move hand closer — FL value decreases

# ── Rain sensor ──
# Wet the sensor surface:
#   RAIN:1
# Dry it:
#   RAIN:0

# ── Doors / ignition ──
# Open a door (or bridge the optoisolator input):
#   DOOR:FL=1,FR=0,RL=0,RR=0,BONNET=0,TRUNK=0
# Turn ignition key:
#   IGN:1

Verify BCM event bus

# Check BCM logs for parsed sensor data
sudo journalctl -u bcm-headunit --no-pager -n 50 | grep -E "temp|light|parking|rain|door|ignition"

# Expected log entries:
#   Arduino serial listener started: /dev/ttyACM0
#   Temperature: 23.5°C
#   Light level: 512
#   Parking: FL=45 FR=123 RL=200 RR=180
