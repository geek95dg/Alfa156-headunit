08 — WiFi & Bluetooth MediaTek MT7921 combo card — P2P-GO AA Wireless & BT 5.2 carkit

Overview

The kiosk uses a MediaTek MT7921 M.2 combo card for both WiFi and Bluetooth. The PCIe side ([14c3:7961]) drives WiFi 6 via the mainline mt7921e driver; the USB side ([0489:e0cd], MediaTek/Foxconn) provides Bluetooth 5.2 through the standard btusb+btmtk stack. Both come up from a single M.2 Key E slot with shared antennas, and both need the firmware-mediatek package (Debian non-free-firmware repo) to load — without it, the WiFi reports hardware init failed and BT reports Failed to load firmware file (-2).

Why MT7921 over the original Intel combo

The M910q ships with an Intel 8265 (WiFi) + Intel 8087 (BT) combo. The 8265 has a self-managed regdom pinned to country 00 that flags every 5 GHz channel as NO-IR for AP mode regardless of iw reg set, and the 8087 has a documented tx-timeout that resets the controller mid-pair after ~15 minutes uptime. MT7921 has neither problem — 5 GHz ch149 P2P-GO at 80 MHz VHT comes up first try, and BT 5.2 sessions are stable. See wireless.wiki.kernel.org.

Feature Intel 8265 + 8087 (original) MediaTek MT7921 (current)
WiFi standard 802.11ac (WiFi 5) 802.11ax (WiFi 6), 80 MHz VHT
5 GHz AP / P2P-GO Firmware-locked off (self-managed country 00, NO-IR on UNII-1/3) ch149 first try at 30 dBm
Bluetooth BT 4.2 — tx-timeout after ~15 min, controller resets BT 5.2 — stable
WiFi driver iwlwifi + firmware-iwlwifi mt7921e + firmware-mediatek
BT driver btusb + btintel btusb + btmtk
Form factor M.2 Key E 2230 M.2 Key E 2230 (compatible)

Hardware Installation

M.2 Key E Slot Swap

  1. Power off the M910q and unplug all cables.
  2. Remove the top cover (single thumbscrew on the back).
  3. Locate the M.2 Key E slot — the original Intel 8265 card is held by a single screw.
  4. Disconnect the two IPEX/U.FL antenna pigtails from the Intel card.
  5. Remove the mounting screw, slide out the Intel 8265.
  6. Insert the MT7921 M.2 Key E card at a 30° angle, press down, and secure with the screw.
  7. Reconnect both IPEX/U.FL antenna pigtails to the MT7921 card (MAIN + AUX).

Antenna Pigtails

MT7921 M.2 modules use 2× IPEX/U.FL connectors, identical to the Intel 8265 they replace. Reuse the existing antenna pigtails if they are in good condition. For best WiFi and Bluetooth range, route the antenna cables toward the windshield — metal bodywork behind the dashboard attenuates the signal significantly.

Antenna placement matters

Place antennas as close to the windshield as possible. Glass has much lower RF attenuation than steel. Tuck the pigtails behind the A-pillar trim or above the headliner near the windshield edge for optimal coverage to the phone in a dash mount or cupholder.

Driver Setup

The MT7921 driver (mt7921e for WiFi, btmtk for BT) is included in the mainline Linux kernel since version 5.18. Debian 13 (Trixie) ships with kernel 6.x, so the drivers load automatically. Both radios need the firmware-mediatek package — otherwise the WiFi reports hardware init failed and BT reports Failed to load firmware file (-2) in dmesg. 

# Install firmware (pulls WIFI_MT7961_*.bin + BT_RAM_CODE_MT7961_*.bin
# into /lib/firmware/mediatek/). Debian trixie non-free-firmware repo
# is enabled by default on the NETINST-with-firmware ISO.
apt install firmware-mediatek

# Reload drivers without a reboot (or just reboot)
modprobe -r mt7921e mt7921_common mt792x_lib mt76_connac_lib mt76
modprobe mt7921e
modprobe -r btusb btmtk
modprobe btusb

# Verify the card is detected and firmware loaded
lspci -nn | grep -i mediatek          # expect: [14c3:7961]
lsusb | grep -iE 'mediatek|0489:e0cd' # expect: Foxconn/MediaTek BT
dmesg | grep -E 'mt7921|btmtk' | grep -iE 'firmware|version'
iw dev                                 # expect wlp2s0, type managed
hciconfig -a                           # expect hci0 UP RUNNING, Manufacturer: MediaTek

Successful output shows mt7921e ... WM Firmware Version: ... in dmesg, the interface renamed from wlan0 to wlp2s0, and hciconfig reporting HCI Version: 5.2 ... Manufacturer: MediaTek, Inc.. The WiFi and BT MAC addresses are sequential (offset +1) because both radios share the combo card's vendor MAC block.

WiFi AP — P2P-GO for Android Auto Wireless

Production BCM brings up the AA Wireless hotspot as a Wi-Fi Direct P2P-GO group, not a regular hostapd AP. The protocol Android speaks for wireless AA is Wi-Fi Direct internally, so P2P-GO is what the stock car-kits use — it's protocol-correct, not a workaround. The BCM Python code (src/multimedia/wifi_ap.py:_start_p2p_go) runs wpa_supplicant + wpa_cli p2p_group_add freq=5745 persistent on boot.

Mode SSID Band Purpose Subnet
p2p_go (default) DIRECT-XX (auto by wpa_supplicant) 5 GHz ch149, 80 MHz VHT Android Auto wireless — low latency, high throughput 10.0.0.0/24
hostapd (fallback) ALFA 5 GHz ch149 Alternative if P2P-GO fails (e.g. STA-only firmware) 10.0.0.0/24
ALFA-NET (optional) ALFA-NET 2.4 GHz ch6 (USB dongle only) General connectivity — SSH, phone hotspot relay 10.0.1.0/24

YAML Configuration (config/bcm_config.yaml)

wifi:
  enabled: true
  ssid: ALFA           # used only in hostapd mode; P2P-GO advertises DIRECT-XX
  password: 87654321
  mode: p2p_go         # P2P-GO (Wi-Fi Direct) — correct mode for AA Wireless
  band: a              # 5 GHz
  channel: 149         # UNII-3, 30 dBm on MT7921 worldwide regdom
  country: US
  regdom: US
  share_internet: true
  ip: 10.0.0.1
  netmask: 255.255.255.0
  dhcp_start: 10.0.0.10
  dhcp_end: 10.0.0.50
  alfa_net:
    enabled: true     # requires second radio (USB WiFi dongle)
    interface: ''     # '' = auto-detect a 2nd-PHY radio; or pin e.g. 'wlx'
    ssid: ALFA-NET
    password: AlfaRomeo156
    channel: 6        # 2.4 GHz
    country: US

P2P-GO auto-generates a DIRECT-XX SSID + random WPA2 PSK each boot. wifi_ap.py reads them back from wpa_cli p2p_get_passphrase and writes the real values into wifi.ssid_runtime / wifi.password_runtime so the BT bootstrap hands the phone the right SSID over the AA pairing handshake.

The Android Auto SSID is not user-renameable

In P2P-GO mode the SSID is the spec-mandated DIRECT-XX chosen by wpa_supplicant, and the phone receives it (plus the PSK) over Bluetooth during the AA bootstrap — the user never types it. There is no benefit to renaming it and a wrong format breaks AA connect, so the settings screen no longer surfaces these live credentials. The editable wifi.ssid only applies in the hostapd fallback.

MT7921 interface_combinations: #{AP, P2P-GO} ≤ 1

MT7921 advertises only one AP-or-GO role per radio. The secondary ALFA-NET SSID cannot share the same PHY as the active P2P-GO group — _maybe_start_alfa_net() falls back to a USB WiFi dongle on a separate PHY (auto-detected, or pinned via wifi.alfa_net.interface), or skips ALFA-NET entirely with a log warning. Verify with iw phy phy1 info | grep -A2 'valid interface combinations'.

USB dongle must present a driven interface

ALFA-NET can only start once the dongle shows up in /sys/class/net (check iw dev). A common gotcha: the Realtek RTL8188EUS (lsusb 0bda:8179) needs the r8188eu module — if it's missing from the running kernel (no linux-modules-extra / matching linux-headers for a DKMS build of the aircrack 8188eus driver) the USB device enumerates with driver NONE and no netdev appears, so ALFA-NET correctly skips. The 8188EUS is also 2.4 GHz-only with weak mainline AP support; an MT7612U or RTL8812BU is a more reliable AP dongle.

Bluetooth Setup

Bluetooth is managed by two components: the system-level bcm-bluetooth.service and the application-level BluetoothManager in BCM.

bcm-bluetooth.service

This systemd service runs at boot and configures the Bluetooth adapter:

  • Power on — enables the BT adapter
  • Alias — sets the device name to Alfa156 Headunit
  • Discoverable — makes the adapter visible to nearby devices
  • Pairable — allows incoming pairing requests
  • Agent — registers a pairing agent for passkey confirmation

BluetoothManager (BCM Application)

The BluetoothManager class in the BCM Python application provides:

  • D-Bus pairing agent — handles pairing requests programmatically
  • A2DP sink — receives audio streams from the phone for music playback
  • HFP — hands-free profile for phone calls through the car speakers
  • AVRCP transport control — play/pause/next/previous driven from the dashboard now-playing card (POST /api/media/<action> → bt.cmd.media → BlueZ MediaPlayer1)
  • Auto-connect on boot & wake — see below

Auto-connect on Boot / Wake

A carkit is expected to re-establish the phone link itself, not wait for the user to tap Connect. BCM handles this at two layers:

  • BCM application — on startup (and again on the power.modules_start wake event) BluetoothManager walks the paired+trusted set and connects the first device that answers, retrying in several rounds over ~25 s (a phone isn't reachable in the first second or two after the unit powers on / wakes). An idle sweep every ~30 s also re-links a phone that comes into range mid-drive.
  • BlueZ daemon — /etc/bluetooth/main.conf sets [Policy] AutoEnable=true plus ReconnectAttempts=7 / ReconnectIntervals=1,2,4,8,16,32,64 so bluetoothd re-establishes the audio/HFP profiles to a trusted device on its own after a link drop. Applied by setup-x86.sh / apply-fixes.sh.

No reboot is needed to pick up code changes — restart bcm-headunit.service. On S3 resume the sleep hook already restarts the service, which re-runs the boot auto-connect.

Pairing Flow

  1. Phone discovers "Alfa156 Headunit" in its Bluetooth settings.
  2. Phone initiates a pairing request.
  3. BCM global polling detects the pairing request (polls every 2 seconds).
  4. A passkey confirmation popup appears on the BCM dashboard (works from any screen).
  5. User confirms on the BCM touchscreen — pairing completes; the device is trusted so future boots auto-connect without interaction.

Phonebook & Dialer (PBAP)

On connect, PhonebookSync pulls the phone's contacts (telecom/pb) and combined call history (cch) over PBAP and publishes them on bt.contacts / bt.call_history for the A8 dialer screen (/api/phone/contacts, /api/phone/history).

PBAP runs over obexd, which is a session-bus service. Because bcm-headunit runs headless as root with no login session, PhonebookSync starts its own private D-Bus session bus and obexd for the process — without it dbus.SessionBus() fails with "Unable to autolaunch a dbus-daemon without a $DISPLAY" and the dialer stays empty. obexd's PullAll is asynchronous: it returns a Transfer1 object path, and the vCard file is only complete once the transfer reaches complete (obexd then removes the object). The sync waits for that before reading the file. The phone must also have "Contacts and call-history sharing" enabled for the head unit.

Supported BT Profiles

Profile Function
A2DP Advanced Audio Distribution — high-quality music streaming from phone to car
HFP Hands-Free Profile — phone calls through car speakers and microphone
AVRCP Audio/Video Remote Control — play, pause, skip from SWC buttons and the dashboard now-playing card; also feeds the now-playing metadata
PBAP (PCE) Phonebook Access — pulls contacts + call history for the A8 dialer (via a process-private obexd; see Phonebook & Dialer above)
MAP (MCE) Message Access — advertised in the carkit profile set for the AA bootstrap

Troubleshooting

Problem Cause Solution
mt7921e ... hardware init failed in dmesg firmware-mediatek not installed — driver loads but firmware blob is missing Install: apt install firmware-mediatek. Reload: modprobe -r mt7921e; modprobe mt7921e. Verify ls /lib/firmware/mediatek/WIFI_MT7961* finds the blobs.
bluetooth hci0: Failed to load firmware file (-2) + bluetoothctl segfaults Same root cause as above — BT side of the combo also needs firmware-mediatek Install firmware-mediatek, then modprobe -r btusb; modprobe btusb. hciconfig hci0 up should bring the BD Address out of 00:00:00:00:00:00.
p2p_group_add returns FAIL on ch149 System wpa_supplicant.service is holding wlp2s0 in type managed via D-Bus — pkill misses it Stop the unit first: systemctl stop wpa_supplicant.service. BCM's wifi_ap.py does this automatically when wifi.mode=p2p_go; only relevant for manual testing.
P2P-GO comes up on the wrong frequency Channel-to-MHz mapping mismatch — freq=2437 = ch6 (2.4 GHz), freq=5745 = ch149 (5 GHz) Set wifi.channel: 149 in YAML for the 80 MHz VHT path. wifi_ap.py auto-derives freq: 2.4 GHz uses 2407+5*ch, 5 GHz uses 5000+5*ch.
ALFA-NET not broadcasting alongside AA Wireless MT7921's interface_combinations advertises #{AP, P2P-GO} ≤ 1 — one AP role per radio Plug a USB WiFi dongle on a free port. _maybe_start_alfa_net() detects the second PHY and parks ALFA-NET there. Without a dongle, ALFA-NET is unavailable while AA is active.
Bluetooth not discoverable after boot bcm-bluetooth.service failed, rfkill soft-block, or adapter not powered Check systemctl status bcm-bluetooth. Unblock: rfkill unblock bluetooth. Power: bluetoothctl power on && bluetoothctl discoverable on. hciconfig -a should show UP RUNNING.
Pairing PIN popup never appears on dashboard BCM venv missing dbus-python → D-Bus pairing agent never registers Recreate venv with system site-packages: python3 -m venv --system-site-packages .venv. Check: grep "pairing agent" /opt/bcm/logs/bcm.log.
No audio over A2DP after pairing PipeWire not routing BT audio, or libspa-0.2-bluetooth missing Install: apt install libspa-0.2-bluetooth pipewire-audio. Check routing: wpctl status, pactl list sources short. Restart: systemctl --user restart pipewire wireplumber.
