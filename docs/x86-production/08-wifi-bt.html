08 — WiFi & Bluetooth Fenvi FU-AX1800 (MediaTek MT7921) — Dual-SSID AP & BT Pairing

Overview

The Fenvi FU-AX1800 (MediaTek MT7921 chipset) replaces the stock Intel 8265 wireless card in the Lenovo M910q. While the Intel 8265 provides basic WiFi and Bluetooth, it cannot reliably operate as a 5 GHz access point — a requirement for wireless Android Auto. The Fenvi FU-AX1800 resolves this with full WiFi 6 (802.11ax) support on both 2.4 GHz and 5 GHz bands, plus Bluetooth 5.2.

Why replace the Intel 8265?

The Intel 8265 uses the iwlwifi driver, which does not support 5 GHz AP mode. Android Auto wireless requires a 5 GHz access point for acceptable latency and bandwidth. The MT7921 driver (mt7921e) is mainline since kernel 5.18 and supports both AP mode on 5 GHz and dual-SSID virtual interfaces, making it the ideal upgrade.

WiFi Standard 802.11ac (WiFi 5) 802.11ax (WiFi 6)
5 GHz AP Mode Not supported Supported
Dual-SSID (virtual interfaces) Not supported Supported

Hardware Installation

M.2 Key E Slot Swap

  1. Power off the M910q and unplug all cables.
  2. Remove the top cover (single thumbscrew on the back).
  3. Locate the M.2 Key E slot — the Intel 8265 card is held by a single screw.
  4. Disconnect the two IPEX/U.FL antenna pigtails from the Intel card.
  5. Remove the mounting screw, slide out the Intel 8265.
  6. Insert the Fenvi FU-AX1800 into the same M.2 Key E slot at a 30° angle, press down, and secure with the screw.
  7. Reconnect both IPEX/U.FL antenna pigtails to the Fenvi card.

Antenna Pigtails

The Fenvi FU-AX1800 uses 2× IPEX/U.FL connectors, same as the Intel 8265. Reuse the existing antenna pigtails if they are in good condition. For best WiFi and Bluetooth range, route the antenna cables toward the windshield — metal bodywork behind the dashboard attenuates the signal significantly.

Antenna placement matters

Place antennas as close to the windshield as possible. Glass has much lower RF attenuation than steel. Tuck the pigtails behind the A-pillar trim or above the headliner near the windshield edge for optimal coverage to the phone in a dash mount or cupholder.

Driver Setup

The MT7921 driver (mt7921e) is included in the mainline Linux kernel since version 5.18. Debian 13 (Trixie) ships with kernel 6.x, so the driver is available out of the box. Only the firmware package needs to be installed. 

# MT7921 driver is mainline (kernel 5.18+, Debian 13 has it)
apt install firmware-mediatek

# Blacklist Intel WiFi (prevent conflicts if Intel 8265 is still detected)
echo "blacklist iwlwifi" > /etc/modprobe.d/blacklist-intel-wifi.conf

# Verify the card is detected
lspci | grep -i mediatek
ip link show | grep wl
iw dev

After installing the firmware and rebooting, lspci should show the MediaTek MT7921 device, and ip link should list a wlan0 interface. The iw dev command confirms the wireless interface is operational.

WiFi AP — Dual SSID Configuration

The BCM build uses two SSIDs on a single physical interface via hostapd BSS (Basic Service Set) support. This allows dedicated networks for Android Auto and general connectivity without a second wireless adapter.

SSID Band Purpose Subnet
ALFA_AA 5 GHz (channel 36 or 149) Android Auto wireless — low latency, high throughput 192.168.44.0/24
ALFA_NET 2.4 GHz General connectivity — phone hotspot relay, SSH access 192.168.45.0/24

hostapd Configuration

Create or edit /etc/hostapd/hostapd.conf: 

interface=wlan0
driver=nl80211

# Primary BSS — 5GHz for Android Auto
ssid=ALFA_AA
hw_mode=a
channel=36
ieee80211n=1
ieee80211ac=1
ieee80211ax=1
wpa=2
wpa_passphrase=AlfaRomeo156
wpa_key_mgmt=WPA-PSK
rsn_pairwise=CCMP
country_code=PL

# Secondary BSS — 2.4GHz general
bss=wlan0_1
ssid=ALFA_NET
wpa=2
wpa_passphrase=AlfaNet2026
wpa_key_mgmt=WPA-PSK
rsn_pairwise=CCMP
Dual-SSID requires virtual interface support

Dual-SSID depends on the MT7921 supporting virtual interfaces. Verify with iw list | grep -A5 "valid interface combinations". The output should list support for multiple APs. If not supported by your firmware version, fall back to a single SSID (ALFA_AA on 5 GHz) and use the phone's mobile hotspot for general internet connectivity.

dnsmasq Configuration

Configure DHCP for both interfaces in /etc/dnsmasq.d/bcm-wifi.conf: 

interface=wlan0
interface=wlan0_1
bind-interfaces
dhcp-range=interface:wlan0,192.168.44.10,192.168.44.50,255.255.255.0,24h
dhcp-range=interface:wlan0_1,192.168.45.10,192.168.45.50,255.255.255.0,24h

This assigns IPs in the 192.168.44.x range for the Android Auto network and 192.168.45.x for the general network. The bind-interfaces directive ensures dnsmasq only listens on the specified interfaces, avoiding conflicts with other network services.

Bluetooth Setup

Bluetooth is managed by two components: the system-level bcm-bluetooth.service and the application-level BluetoothManager in BCM.

bcm-bluetooth.service

This systemd service runs at boot and configures the Bluetooth adapter:

  • Power on — enables the BT adapter
  • Alias — sets the device name to Alfa156 Headunit
  • Discoverable — makes the adapter visible to nearby devices
  • Pairable — allows incoming pairing requests
  • Agent — registers a pairing agent for passkey confirmation

BluetoothManager (BCM Application)

The BluetoothManager class in the BCM Python application provides:

  • D-Bus pairing agent — handles pairing requests programmatically
  • A2DP sink — receives audio streams from the phone for music playback
  • HFP — hands-free profile for phone calls through the car speakers

Pairing Flow

  1. Phone discovers "Alfa156 Headunit" in its Bluetooth settings.
  2. Phone initiates a pairing request.
  3. BCM global polling detects the pairing request (polls every 2 seconds).
  4. A passkey confirmation popup appears on the BCM dashboard (works from any screen).
  5. User confirms on the BCM touchscreen — pairing completes.

Supported BT Profiles

Profile Function
A2DP Advanced Audio Distribution — high-quality music streaming from phone to car
HFP Hands-Free Profile — phone calls through car speakers and microphone
AVRCP Audio/Video Remote Control — play, pause, skip, volume from SWC buttons

Verification

WiFi AP

# Check hostapd is running
sudo systemctl status hostapd

# Verify AP mode on wlan0
iw dev wlan0 info  # should show type AP

# List connected clients
iw dev wlan0 station dump

Bluetooth

# Check BT adapter state
bluetoothctl show | grep -E "Powered|Discoverable|Pairable"

# Verify BluetoothManager initialized in BCM
grep "BluetoothManager initialized" /opt/bcm/logs/bcm.log | tail -3

# List paired devices
bluetoothctl devices Paired

Troubleshooting

Problem Cause Solution
hostapd fails: Channel 36 not allowed Regulatory domain blocks the channel Set country_code=PL in hostapd.conf and run iw reg set PL. Try channel 149 as an alternative. Verify with iw list | grep -A20 "Frequencies".
Dual-SSID not working MT7921 firmware does not support multiple virtual APs Run iw list | grep -A5 "valid interface combinations". If only 1 AP is listed, remove the bss=wlan0_1 block from hostapd.conf and use a single SSID. Update firmware: apt update && apt upgrade firmware-mediatek.
Bluetooth not discoverable bcm-bluetooth.service failed or adapter not powered Check systemctl status bcm-bluetooth. Manually run bluetoothctl power on and bluetoothctl discoverable on. Verify adapter exists with hciconfig -a.
Pairing request times out BCM polling missed the D-Bus signal or agent not registered Check BCM logs: grep -i "pairing\|agent" /opt/bcm/logs/bcm.log | tail -20. Restart BCM: systemctl restart bcm. Ensure BluetoothManager is enabled in BCM config.
No audio over A2DP PipeWire not routing BT audio to the DAC Check PipeWire status: wpctl status. Ensure the BT source is connected: pactl list sources short. Restart PipeWire: systemctl --user restart pipewire wireplumber.
WiFi interface not appearing after reboot Missing firmware or driver not loaded Verify firmware installed: dpkg -l firmware-mediatek. Check kernel module: lsmod | grep mt7921. Load manually: modprobe mt7921e. Check dmesg: dmesg | grep mt7921.
