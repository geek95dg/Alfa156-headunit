Verification Complete checklist, diagnostic commands, and troubleshooting for the final production build

Overview

This is the final verification checklist after completing all installation steps (sections 01–11). Work through each category systematically, marking items as Pass or Fail. Any failures should be resolved using the troubleshooting table at the bottom of this page before considering the build production-ready.

When to run this checklist

Run the full checklist after completing the initial build, after any hardware changes (new display, new WiFi card, etc.), and after major software updates. For day-to-day operation, the quick diagnostic script in section 3 covers the essentials.

Quick Diagnostic Commands

Run this all-in-one diagnostic script to check the most critical subsystems at a glance. Copy and paste the entire block into a terminal: 

#!/bin/bash
# BCM Quick Diagnostics — run as root or with sudo
echo "============================================"
echo "  BCM v8.5 — Quick Diagnostic Report"
echo "============================================"
echo ""

# Core system
echo "--- Core System ---"
echo -n "BCM Flask (port 5002): "
curl -s -o /dev/null -w "%{http_code}" http://localhost:5002 2>/dev/null || echo "FAIL"
echo ""
echo -n "BCM service: "
systemctl is-active bcm-headunit 2>/dev/null || echo "inactive"
echo -n "Ignition watcher: "
systemctl is-active bcm-ignition-watcher 2>/dev/null || echo "inactive"
echo ""

# Displays
echo "--- Displays ---"
xrandr --listmonitors 2>/dev/null || echo "xrandr not available"
echo ""

# ECU / OBD
echo "--- ECU / OBD ---"
echo -n "K-Line adapter: "
ls /dev/ttyUSB_kline 2>/dev/null && echo "OK" || echo "NOT FOUND"
echo -n "ECU comms: "
grep -c "controller found\|RPM" /opt/bcm/logs/bcm.log 2>/dev/null || echo "0"
echo " matches in bcm.log"
echo ""

# Connectivity
echo "--- Connectivity ---"
echo -n "WiFi AP (hostapd): "
systemctl is-active hostapd 2>/dev/null || echo "inactive"
echo -n "Bluetooth: "
systemctl is-active bluetooth 2>/dev/null || echo "inactive"
echo -n "LTE modem: "
ip addr show wwx* 2>/dev/null | grep -q "inet " && echo "ONLINE" || echo "OFFLINE"
echo -n "GPS fix: "
grep -c "fix" /opt/bcm/logs/bcm.log 2>/dev/null || echo "0"
echo " fix entries in log"
echo ""

# Audio
echo "--- Audio ---"
echo -n "USB DAC: "
aplay -l 2>/dev/null | grep -qi "usb\|dac" && echo "DETECTED" || echo "NOT FOUND"
echo -n "PipeWire: "
systemctl --user is-active pipewire 2>/dev/null || echo "inactive"
echo ""

# Android Auto
echo "--- Android Auto ---"
echo -n "autoapp binary: "
ls /usr/local/bin/autoapp 2>/dev/null && echo "OK" || echo "NOT FOUND"
echo -n "Xvfb (:99): "
ps aux | grep -v grep | grep -q "Xvfb.*:99" && echo "RUNNING" || echo "NOT RUNNING"
echo ""

# Power / Boot
echo "--- Power / Boot ---"
echo -n "Suspend support: "
cat /sys/power/state 2>/dev/null || echo "unknown"
echo -n "Boot time: "
systemd-analyze 2>/dev/null | head -1 || echo "unknown"
echo ""

# Arduino
echo "--- Arduino ---"
echo -n "Input Arduino: "
ls /dev/ttyACM0 2>/dev/null && echo "OK" || echo "NOT FOUND"
echo -n "Output Arduino: "
ls /dev/ttyUSB_arduino_out 2>/dev/null && echo "OK" || echo "NOT FOUND"
echo ""

echo "============================================"
echo "  Diagnostic complete"
echo "============================================"
Save as a script

Save this as /opt/bcm/scripts/diagnostics.sh and make it executable with chmod +x. Run with sudo bash /opt/bcm/scripts/diagnostics.sh for a quick health check at any time.

Common Issues & Fixes

This table compiles the most common issues encountered across all build stages, along with their symptoms, root causes, and fixes.

Issue Symptom Cause Fix
BCM won't start systemctl status bcm-headunit shows failed Python venv broken or missing dependency Re-run cd /opt/bcm && source venv/bin/activate && pip install -r requirements.txt
No display output Both screens black after boot DP-to-HDMI adapters not connected or X11 not starting Check adapter connections; verify xinit runs in .bash_profile; check /tmp/bcm-xinput.log
Displays mirrored Both screens show same content xrandr not configured for separate outputs Verify .xinitrc has xrandr --output DP-1 --auto --output DP-2 --auto --right-of DP-1
Touch offset Taps land in wrong position Touch device mapped to wrong display or not calibrated Run xinput map-to-output <touch-id> DP-1; check coordinate transform matrix
No audio Dashboard loads but no sound from speakers USB DAC not default sink or PipeWire not running wpctl set-default <dac-sink-id>; verify systemctl --user status pipewire
K-Line not detected /dev/ttyUSB_kline missing udev rule not installed or adapter unplugged Check /etc/udev/rules.d/99-bcm.rules; run udevadm trigger; reconnect adapter
No ECU data Dashboard shows 0 RPM, 0 km/h K-Line wiring issue or wrong baud rate Verify K-Line wiring (Tx/Rx/GND); check baud rate is 10400 in config
WiFi AP not starting hostapd fails immediately WiFi card does not support AP mode on 5 GHz Check iw list | grep AP; consider Fenvi AX200 upgrade; try 2.4 GHz as fallback
BT not discoverable Phone cannot find BCM in BT scan Bluetooth service not running or adapter powered off sudo systemctl restart bluetooth; bluetoothctl power on; bluetoothctl discoverable on
LTE no internet Huawei E3372 plugged in but no connectivity Modem not switching to HiLink mode or no SIM Check lsusb for Huawei device; verify SIM has data; check ip route for default gateway
GPS no fix Position shows 0,0 or "No fix" GPS antenna obstructed or gpsd not running Ensure GPS puck has sky view; check systemctl status gpsd; verify /dev/ttyACM* or /dev/ttyUSB*
Suspend not working System does not enter S3 on power button BIOS S3 disabled or systemd sleep target masked Enable S3 in BIOS (Advanced → Power); sudo systemctl unmask sleep.target suspend.target
Resume fails System does not wake from S3 or hangs on resume USB wake not enabled or GPU driver issue Enable USB wake in BIOS; check cat /proc/acpi/wakeup; update Intel GPU firmware
Splash not showing Black screen during boot, then dashboard appears Splash service failed or video file missing Check journalctl -u bcm-splash-main; verify splash video exists at configured path
GRUB menu appears GRUB menu visible for a few seconds before boot GRUB timeout not set to 0 Set GRUB_TIMEOUT=0 in /etc/default/grub; run sudo update-grub
Kernel messages on screen Scrolling text visible during boot Quiet boot not configured Add quiet loglevel=0 vt.global_cursor_default=0 to GRUB_CMDLINE_LINUX_DEFAULT; run sudo update-grub
Arduino not responding No sensor data or relay control Serial port name changed or Arduino disconnected Check ls /dev/ttyACM* /dev/ttyUSB*; verify udev rules; re-flash Arduino firmware if needed
AA touch offset Taps on AA screen land in wrong position Canvas size mismatch between browser and Xvfb Check display.multimedia.width/height matches Xvfb resolution; verify xdotool coordinate mapping

Next Steps

Once all checklist items pass, the BCM build is production-ready. Here are the recommended next steps:

  • Return to the Overview for a summary of the complete build and links to all documentation sections.
  • OTA updates: The BCM software can be updated in-place by pulling the latest changes from the git repository and re-running the setup script: 
    cd /opt/bcm
git pull
sudo bash setup-x86.sh
    This preserves your bcm_config.yaml and only updates the application code, templates, and systemd services.
  • Backup your configuration: Copy /opt/bcm/config/bcm_config.yaml and /etc/udev/rules.d/99-bcm.rules to a USB drive or cloud storage. These are the only files that contain your specific hardware mappings.
  • Create a disk image: Once everything is verified, create a full disk image with dd or clonezilla for disaster recovery. A 256 GB NVMe image compresses to ~8–15 GB.
